Home Agent شركة لتركيب أنظمة البيت الذكي في مصر. كانت تحتاج أكثر من موقع تعريفي: موقعًا عامًا يحوّل الزوار إلى طلبات معاينة، ولوحة تحكم يدير منها الفريق المحتوى ومسار المبيعات بدون الحاجة لمطوّر.

بنيت المنصة في الفترة من 27 أكتوبر إلى 8 نوفمبر 2026 — 122 commit من مستودع فارغ حتى [homeagenteg.com](https://homeagenteg.com).

## ماذا بنيت

**الموقع العام** عربي بالكامل ومن اليمين لليسار. يستطيع الزائر تصفّح الباقات وكتالوج المنتجات، وحجز معاينة، والحصول على ترشيح لباقة مناسبة من خلال اختبار قصير من 5 أسئلة، وتجربة عرض تفاعلي للبيت الذكي.

**لوحة التحكم** تؤدي وظيفتين:

- **نظام لإدارة المحتوى** — يدير الفريق المنتجات والباقات والمشاريع السابقة والأسئلة الشائعة وإعدادات الموقع ورفع الصور. لا يوجد شيء ثابت في الكود.
- **نظام لإدارة العملاء** — كل طلب معاينة يتحول إلى عميل محتمل يمر بمسار مبيعات من 9 مراحل (من *جديد* و*تم التواصل* مرورًا بـ*المعاينة* و*عرض السعر* حتى *تم البيع*)، مع ملاحظات وسجل نشاط وفلاتر وتقارير بنسب التحويل: كم طلبًا تحوّل إلى معاينة، وكم معاينة تحوّلت إلى بيع.

## التقنيات

- **Next.js 15 (App Router) و React 19 و TypeScript** للتطبيق كله
- **Tailwind CSS و shadcn/ui** للواجهة
- **React Query** لحالة الخادم، و **React Hook Form مع Zod** للنماذج والتحقق
- **Supabase** — قاعدة Postgres والمصادقة و Row Level Security والتخزين للصور
- **Cloudflare Workers** عن طريق OpenNext للاستضافة
- **Vitest** لاختبارات الوحدات و **Playwright** للاختبارات الشاملة

## أصعب جزء: الأمان بدون تسجيل دخول

المشكلة الأهم كانت التحكم في الصلاحيات. أي زائر يجب أن يستطيع **إرسال** طلب معاينة — بدون حساب أو تسجيل دخول. لكن **قراءة** الطلبات أو **تعديلها** مقصورة على الموظفين فقط، ولكل دور صلاحياته: *admin* له كل الصلاحيات، و*marketing* يعمل على المحتوى والعملاء.

لم أضع هذا المنطق في كود التطبيق فقط، بل في قاعدة البيانات نفسها باستخدام **Row Level Security**، بحيث حتى لو أرسل أحد طلبًا مباشرًا للـ API لن يستطيع قراءة بيانات الآخرين. الفكرة بشكل مبسّط:

```sql
-- Anyone can create a lead...
create policy "public can submit a request"
  on leads for insert
  to anon
  with check (true);

-- ...but only signed-in staff can read them.
create policy "staff can read leads"
  on leads for select
  to authenticated
  using (is_staff());
```

وبذلك يكتفي التطبيق بعرض الشاشات المناسبة — وقاعدة البيانات هي الحارس الحقيقي.

## تنبيهات لا تعطّل الأهم

عند وصول طلب جديد، يصل للفريق تنبيه فوري على **Telegram** وعلى **البريد الإلكتروني** (Resend). القاعدة التي التزمت بها: **حفظ الطلب أولًا دائمًا.** إذا تعطّل Telegram أو خدمة البريد، يرى الزائر رسالة نجاح ويظل الطلب محفوظًا في النظام، ويتم تسجيل فشل التنبيه بدلًا من إفشال الطلب.

```ts
// Simplified
const lead = await saveLead(data); // must succeed
await Promise.allSettled([notifyTelegram(lead), notifyEmail(lead)]); // best effort
return lead;
```

## الاختبارات

لأن الشركة ستستخدم النظام يوميًا، غطّيته باختبارات وحدات بـ Vitest للمنطق والتحقق من البيانات، واختبارات شاملة بـ Playwright للمسارات الأساسية: حجز معاينة، وتسجيل الدخول، ونقل العميل عبر مراحل المبيعات.

## ما سآخذه للمشروع القادم

- ضع قواعد الصلاحيات في قاعدة البيانات، وليس في الواجهة فقط.
- صمّم العمليات الجانبية (البريد والتنبيهات) بحيث يمكن أن تفشل دون أن تُفشل العملية الأساسية.
- ابنِ لوحة التحكم مبكرًا — عندما يستطيع العميل تعديل كل شيء، يستمر الموقع في التحسّن بدونك.
